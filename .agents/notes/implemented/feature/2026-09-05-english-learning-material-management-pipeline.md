# Agent Note: English-learning material management pipeline

Status: implemented

English | [中文](2026-09-05-english-learning-material-management-pipeline.zh.md)

## Problem

The english-learning dashboard shipped a designed but disconnected material pipeline: the 资料 tab was a hardcoded three-item mock, the upload and AI-recommend modals had no file input and no backend route, chat agents joined no preset so the four material skills were invisible, and the skills referenced tool names (`parse_material`, `generate_*`) that exist nowhere in the repository. Adding a learning material and having the agent digest it was impossible end to end.

## Decision

The pipeline runs on the stock tool set, with no new canonical wire surface:

- **Materials are Markdown files under the launch workspace** at `<cwd>/.english-learning/materials/`, one file per material (`<timestamp>-<name>.md`). The dashboard bundle serves `GET/POST/DELETE /api/materials` reading and writing that directory; the directory is git-ignored. Files under the launch workspace sit inside the agent's sandbox root, so the chat agent reads them with the stock `read` tool.
- **The four preset skills reach chat agents without mounting the preset composition.** The dashboard bundle registers a second `skill-filesystem` provider on `ctx.skills` scoped to the preset's `skills/` directory (`includeDefaultRoots: false`, watching off); the directory path resolves from the `@deepseek-ai/dsh-agent-presets` package location, never from the process cwd. The skills were rewritten to use only existing tools: `read` for material files, `web_search` in `material-search`, and in-reply output instead of the nonexistent `generate_*` and `parse_material` tools.
- **Analysis is a chat message.** The UI's 分析 action sends a prompt naming the material and its file path; the agent loads `material-digest`, then `knowledge-extractor`, reads the file, and produces the structured report in the reply. The analysis status badge is client-session state, not persisted data.
- **The homepage ability dimensions are aggregates of agent-written learning records.** The digest and exercise skills end with a record step: the agent writes one small JSON file per activity into `.english-learning/progress/` (`{time, kind: 'digest'|'exercise', skill, material?, level?, vocabulary?, count?, correct?}`) with the stock `write` tool. The bundle serves `GET /api/progress`, which folds those files into per-ability activity counts, graded accuracy (summed `correct`/`count` over graded exercise rounds), XP (digest 40, exercise 20, vocabulary word 5), consecutive learning days, and the latest records; the dashboard derives the skill-card scores (20 per activity, capped at 100), level path, top-bar XP bar, and streak from that summary and re-polls every 30 seconds.
- **Training is an interactive loop, and vocabulary persists across sessions.** The `exercise-generator` skill runs one dimension at a time — pose one 3-5 question set, wait for answers, grade with correct answers and explanations, write the graded exercise record, then offer the next dimension; skipped sets write nothing. The `material-digest` skill additionally banks every extracted word list into `.english-learning/vocabulary/` (`{time, material, level, words:[{word, definition, example}]}`), served by `GET /api/vocabulary` and shown in a 词汇 tab with a one-click review prompt that asks the agent to quiz five banked words. The dashboard's material rows carry an analyze action and a practice action, and the accuracy read-out appears on the skill card next to the exercise count.
- **Material acquisition is ability-aware and autonomous.** A patch layer overrides the base `tool-web` row with `fetch: true` (repeating the base row's `searchTimeoutMs`, since a non-insert patch replaces the whole config), so the `web_fetch` tool joins `web_search`. The `material-search` skill acquires end to end: read the progress records to assess the learner's CEFR level and weakest dimension, search for matching material, `web_fetch` candidate pages until one yields body text, and `write` it into the materials directory with a source line — the dashboard's materials list picks it up on its next poll. The dashboard's ✨ AI 找资料 modal sends the acquisition prompt with an optional topic.

## Alternatives considered

**Mount the preset composition (`agentPreset` + an `agent-presets` row).** Lost for now: the preset composition carries unverified wiring (an `inject: ['skills']` on rows that the standard preset does not use, a `config.skills.roots` key `skill-filesystem` does not define) and would swap the working model/search stack (exa search, preset LLM config) behind this deployment's model settings. Mounting it remains the path if per-preset composition is later needed; the composition defects must be fixed first.

**Implement `parse_material` and `generate_*` as tool packages.** Lost: text materials need no parsing tool, and exercise generation is a prompting task the model performs in-reply. Dedicated tools would add four packages with no behavior the stock tools lack for this content class.

**Store materials in `settings.yaml` or the JSON KV store.** Lost: settings are configuration, not content blobs, and KV-stored material text would sit outside the agent's sandbox root where its file tools cannot read it.

## Consequences

Adding, listing, and deleting materials works from the dashboard; analyzing a material runs the digest → knowledge-extraction flow and banks its words; the AI-acquire flow searches, fetches, and files a level-matched material; and practice rounds are graded with per-dimension accuracy (verified end to end on a scratch instance, including an organically agent-written progress record). Ability dimensions reflect only what the agent actually recorded: a fresh deployment shows zeroes everywhere until materials are analyzed, exercises are graded, and vocabulary is banked; the record and vocabulary files are the single source — hand-editing them changes the dashboard. Grading fidelity depends on the model following the interactive pacing; a model that dumps all dimensions at once degrades the loop but writes no false records (skipped sets write nothing). Backend changes still require a server restart because the webserver routes live in the bundle plugin, while the web frontend rebuild reaches the browser on reload. Materials are text-only (TXT/MD/SRT/VTT and pasted text); PDF/audio/video extraction remains unimplemented, and speaking practice is text-based reading-aloud without speech tooling. The daily missions tab is still unwired. The preset composition remains dormant with the wiring defects above.
