# Agent Note: 英语学习定级测评

Status: implemented

[English](2026-09-05-english-learning-placement-assessment.md) | 中文

## 问题

英语学习应用没有任何初始能力测评。Agent 对学习者的认知来自两个互不相通的来源:设置页的"当前水平"只存在于 React state(刷新即丢,从不发给 agent),`material-search` 技能从资料难度记录推断水平、无记录时按 A2–B1 兜底。新学习者因此从一个硬编码的猜测起步,无视学习者本人能提供的自述;学习者在设置里选的水平也既不能在刷新后保留,也到不了 agent。

## 决策

**`.english-learning/profile.json` 是唯一的学习者定级记录。** 两个写入方产出同一份 `{time, kind: 'placement', source, currentLevel, skills?, weakSkills?, summary?}` 文档:测评技能写入时 `source: 'placement'`,面板记录手选水平时 `source: 'manual'`。后一次写入整体覆盖——最新意图获胜,无论它来自重测还是设置页。

- **测评是聊天技能,不是新协议。** 新的 `placement-assessment` 技能(位于 preset 的 `skills/` 目录,自动注册)运行 3–4 轮自适应对话——背景、阅读任务、写作任务、可选的口语近似——然后评估总体 CEFR 水平和分项估计,用现有 `write` 工具写入档案。面板的首启引导弹窗和设置页的"重新测评"按钮都发送固定 prompt,指名技能和档案路径。
- **读写可观测,听说靠估计。** 文字对话无法测试听说技能,技能把 `skills` 里对应条目标注为基于自述和词汇广度的估计。消费方把该映射当参考值:`weakSkills` 指出最弱的 1–2 个维度。
- **面板通过 `GET /api/profile` 读档案**(容错解析——文件缺失或损坏读作"无档案"),通过 `POST /api/profile` 写手选水平,后者校验 CEFR 合法性并标注 `source: 'manual'`。App 在与进度、词汇相同的 30 秒轮询里读取它。
- **手选统一进档案。** 保存设置页会上报变更后的水平,agent 因此能看到手选结果,选择也能在刷新后保留。设置页下拉从生效水平初始化,UI 不会在评定结果旁边显示过期值。
- **`effectiveLevel` 排定水平来源顺序:** 先档案,再设置手选,最后内置默认值。顶栏徽章、技能卡水平区间、AI 找资料文案都渲染 `effectiveLevel`。
- **技能优先读档案。** `material-search` 先读 `profile.json` 取当前水平和薄弱维度,再读进度记录,最后落到 A2–B1 兜底;`exercise-generator` 的难度匹配同样引用档案。

## 已考虑的替代方案

**结构化测评表单(agent 输出题目 JSON,面板全屏渲染表单)。** 暂时放弃:它需要新的结构化消息协议、答题提交路由和表单组件,成本约为聊天式的 3–4 倍;而聊天流已经具备流式输出、历史保留和逐轮难度自适应。聊天面板本来就是本应用与 agent 协作的既定交互面。

**通过 dsh-settings 把设置页 `currentLevel` 持久化到 settings.yaml。** 放弃:档案文件已经是 agent 可读的定级记录,再持久化一份会分裂事实源。设置页下拉保留为测评前的显示值。

## 后果

首次访问者会看到引导弹窗(直到完成测评,或通过 `placement-modal-dismissed` localStorage 标记关闭),测评在现有聊天面板中进行,评定后的水平流入顶栏徽章、技能卡、AI 找资料文案、资料获取和练习难度。后端改动需要重启服务(webserver 路由在 bundle 插件里);前端重新构建后刷新浏览器即可生效。测评质量取决于模型遵循多轮节奏——一次性倾倒所有轮次的模型会拉低评估质量,但不会污染存储,因为档案解析器拒绝格式不合的文档。其余设置字段(目标水平、每日目标、显示)仍然不持久化;该缺口维持原状。
