# Agent Note: 英语学习阅读理解练习页面

Status: implemented

[English](2026-09-06-english-learning-reading-practice.md) | 中文

## 问题

阅读是唯一既没有页面也没有技能模板的练习维度：exercise-generator 技能有听力、词汇、口语、写作的模板，唯独没有阅读理解，阅读轮次只能靠模型即兴发挥。听力页验证了 quiz 形态（短文加带答案键的四选一题），口语页验证了管线可推广，阅读两者都需要。

## 决策

**阅读练习端到端复用听力 quiz 管线，并借此把两个 quiz 形态的能力收敛到共享核心。**

- **`quiz.ts` 持有 quiz 形态契约。** 听力的解析/分类器与新加的阅读兄弟模块几乎是克隆，因此容错解析与 write 调用分类收敛到一个零依赖模块，按文档 kind 和会话文件名参数化；`listening.ts` 与 `reading.ts` 是薄特化（`.english-learning/listening-session.json` / `reading-session.json`，kind 为 `listening-exercise` / `reading-exercise`）。听力的公开 API 不变。
- **`/reading` 页面是去掉音频的听力页。** 同样的流程——选来源（资料或话题），技能的页面驱动分支（请求标记「来自阅读练习页」）写入练习，SSE `readingExercise` 送达，页面按答案键批改，`POST /api/reading/result` 合成标准 `{kind: 'exercise', skill: 'reading'}` 记录后删除会话；`GET /api/reading` 恢复刷新后的轮次。差异：原文即内容，渲染为始终可见的阅读卡，没有播放器，也没有先听后看的原文隐藏。
- **`PracticeShared.tsx` 持有页面外壳。** 头部、来源选择介绍、生成中面板、得分卡和四选一题卡是共享组件，由听力、阅读、口语三个页面消费；页面只保留各自的差异部分（播放器、阅读卡、口语句卡）。页面主题色通过每页的包装类由 CSS 驱动。
- **技能补上了缺失的阅读模板。** exercise-generator 现在文档化了阅读理解练习及其页面驱动分支（80-200 词短文出 3-5 题，考查主旨、细节、推断和词义）；该分支自己绝不写 progress 记录。

## 备选方案

**第四个独立解析模块。** 输给 `quiz.ts`：阅读契约与听力逐字节相同、仅 kind 字符串不同，第三份解析/分类骨架克隆只会带来复制漂移。

**覆盖三种能力的通用「练习页」组件。** 暂缓：口语交互（录音、识别、逐句尝试）与 quiz 页几乎共享不了正文，强行合并会让不相关的状态机互相耦合，所以只共享外壳。

**把阅读拆成词汇训练。** 否决：词汇复习已有聊天流程（词汇练习）；页面针对的是短文理解，正是仪表盘阅读维度统计的内容。

## 后果

轮次完整性与过期语义与听力、口语管线一致：跳过或写坏的写入让页面停在可取消态，放弃的会话文档会被再次提供并被覆盖，无待处理会话时提交返回 409 并提示未计入。quiz 收敛意味着 quiz 契约的变更只落一处；重构未改变听力页的公开 API 和测试。阅读原文完整到达浏览器——这是阅读的固有属性，也是先听后看隐藏只存在于听力页的原因。

## 测试

`reading.ts` 由 `packages/bundle/english-learning/tests/reading.spec.ts` 与听力、口语规格并列做单元测试：容错解析矩阵、对听力文档的 kind 区分、路径匹配、write 分类。页面流程（作答、提交、XP 更新、刷新恢复）经真实端点人工验证。
